# Mafia — phone-first P2P web game

Static site on Vercel. No backend. Players connect peer-to-peer over WebRTC using
Trystero (signaling via public Nostr relays). The room creator's phone is the
**host**: it is also a normal player, but it holds the authoritative game state,
runs all rules, and sends each peer only that peer's private view.

## Stack

- Vite + vanilla JS (ES modules). No UI framework, no other deps.
- `trystero` (latest, currently 0.26.x) — **read its README in `node_modules/trystero`
  before writing net code; do not guess the API.** Use the default (Nostr) strategy.
- Vercel auto-detects Vite (`npm run build` → `dist/`). No vercel.json needed.

## Files

```
index.html
package.json          scripts: dev, build, preview, test ("node src/game.test.js")
src/main.js           UI: screens, rendering, local UI state, wake lock, persistence
src/net.js            Trystero wrapper: host + client message plumbing
src/game.js           PURE game logic, no DOM, no network (importable from Node)

src/style.css
```

Keep it to these files.

## Networking (src/net.js)

- `joinRoom({ appId: 'mafia-phone-p2p-v1' }, roomCode)`.
- Optional TURN: one exported `TURN_SERVERS = []` constant passed through Trystero's
  TURN/rtc config option, with a `// ponytail:` comment ("add a TURN server if
  players on mobile data can't connect").
- Room code: 4 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (no ambiguous chars),
  generated by the creator. Share link: `${location.origin}/?room=CODE`.
- Actions (Trystero action names must be short):
  - client → host: `hello` `{ name, token }`, `act` `{ kind, target }`
  - host → one client: `view` (that player's private view), `err` `{ msg }`
- Every client, on every `onPeerJoin`, sends `hello` to that peer. Only the host
  handles `hello`. Non-hosts ignore `hello`.
- A client locks onto the **first peer that sends it a `view`** as `hostPeerId` and
  ignores `view`/`err` from any other peer from then on. (It re-locks only if that
  host peer leaves and a new view arrives, which is the host-reload case below.)
- Join timeout: if no `view` arrives within 12 s, show "Room not found or host
  offline" with a Retry button.
- The host never sends itself messages. Its own UI gets `viewFor(state, hostPlayerId)`
  directly after every state change.
- Host: after every state change, send each connected player their own
  `viewFor(...)`. Never send the full state or anyone else's role.

### Identity and reconnects

- Each device keeps a random `token` (crypto.randomUUID) in localStorage.
- The host maps `token → player`. When a `hello` arrives with a known token, the host
  rebinds that player to the new peerId, marks them connected and sends the current
  view. This is how page reloads and phone sleep/wake recover.
- Unknown token:
  - In the lobby: validate the name (trim it, 1–16 chars, unique
    case-insensitively, room not full at 20). If invalid, send `err`.
  - Mid-game: send `err` "Game already in progress".
- `onPeerLeave` → mark the player disconnected (in the lobby, remove them entirely).
- The client saves `{ room, name, token }` to localStorage. On load, if the URL has
  `?room=` and the saved session matches, it auto-rejoins.
- Host reload: the host saves the full game state to localStorage
  (`mafia-host-<CODE>`) after every change. On load, if a saved host state exists for
  the session's room, it resumes as host with that state (all players marked
  disconnected until they re-`hello`). Clients see the old host peer leave and the new
  one join, send `hello`, get views, and continue.
- Every localStorage access is wrapped in try/catch, and the app must still work
  without storage.

## Game logic (src/game.js) — pure functions over a plain state object

```
state = {
  code, phase, round,
  config: { mafia, doctor, detective, jester, spice },
  nextQuestion: null, usedQuestions: [],   // decoy-question source, see Night
  players: [{ id, token, name, role, alive, connected, isHost }],
  ready: {},          // playerId -> true (role-reveal phase)
  night: { selections: {}, locked: {}, choice: {} },  // selections/locked keyed by playerId, choice keyed by role
  saveStreak: null,   // { targetId, count } doctors' consecutive save target
  votes: {},          // playerId -> targetId | 'skip'
  lastEvent: null,    // { type:'night', killedId|null } | { type:'vote', eliminatedId|null, tally }
  detectiveLog: [],   // shared by the detective team: [{ round, targetId, isMafia }]
  funLog: [],         // civilian/jester decoy-question answers, revealed only at game over
  winner: null,       // 'town' | 'mafia' | 'jester'
  winnerIds: []       // for jester: [jesterId]
}
```

Phases: `lobby → roles → night → dawn → vote → verdict → (night | over)`; `over → lobby`.

Export roughly: `createGame(code)`, `addPlayer`, `removePlayer`, `setConfig`,
`validateStart(state) → string|null`, `startGame(state, rng)`,
`applyAction(state, playerId, action) → error string|null`, `advance(state)`
(called by the host's timers for dawn/verdict), `viewFor(state, playerId)`.
Inject `rng` (default `Math.random`) so tests are deterministic.

### Lobby / config validation (`validateStart`, also shown live in the lobby UI)

- `n` = number of players. Counts are integers, all ≥ 0.
- `mafia >= 1`.
- `mafia + doctor + detective + jester <= n` → "Not enough players for these roles
  (need X, have N)".
- `mafia < n - mafia` (mafia must be strictly fewer than non-mafia, otherwise they
  win at once) → "Too many mafia for N players".
- `n >= 3` (minimum).
- Steppers clamp: no negatives, and "+" is disabled when it would break the rules.
  The Start button is disabled and shows the first failing reason.
- Remaining players become `civilian`.
- Only the host can change config or start. Everyone sees the config read-only.

### Roles phase

- `startGame` shuffles roles with Fisher–Yates using `rng` and resets `alive`,
  `night`, `votes`, `detectiveLog`, `saveStreak`, `winner` and `ready`. `round = 1`.
- Every player sees their role card (tap to flip). Mafia, doctors and detectives
  also see their teammates' names. Each player taps "I'm ready". When **all alive players** are ready → `night`.

### Night — every night role works as a team (consensus, then lock)

The mafia, doctor and detective teams all use the **same mechanism**. Implement it
once, generically, keyed by role. Each team makes **one** choice per night.

- Teammates know each other. On the role card, mafia, doctors and detectives all see
  their teammates' names.
- Eligible targets (all alive):
  - mafia: non-mafia players.
  - doctor: anyone, self included, **except** a player who was the doctors' chosen
    target on each of the last 2 nights (no one can be saved more than 2 nights in
    a row).
  - detective: anyone who is not a detective.
- **Live selection:** tapping a target sends `act { kind:'select', target }` at once
  (not locked). The host stores it in `night.selections[playerId]` and pushes
  updated views to that player's living teammates in real time. Tapping another
  target changes it, and tapping the same one again clears it.
- Every target card shows a chip with the name of each teammate currently on it
  (including "You"). A locked selection's chip is solid with a 🔒. Chips animate in
  and out as picks change. Ineligible targets are hidden, except the doctor's
  blocked player, who is shown greyed out with "Saved 2 nights in a row".
- **Lock:** "Lock in" (enabled once something is selected) sends
  `act { kind:'lock' }`. That locks the player's current selection, and after that
  the host rejects any more `select`/`lock` from them.
- **Team resolution** (`teamChoice(role)`): once **all alive members of a team**
  have locked, the team's choice is the plurality of their locked picks, with ties
  broken by `rng` among the tied players. It is computed once and stored in
  `night.choice[role]`.
- **Detective result:** as soon as the detective team's choice is resolved (even
  while other teams are still choosing), every living detective is shown
  "<name> is Mafia" / "<name> is not Mafia" for **that one chosen player only**.
  The jester counts as "not Mafia". The result is appended to the shared
  `detectiveLog` (`[{ round, targetId, isMafia }]`), and all detectives, alive or
  dead, see the full history. Individual detective picks are never shown as results.
- **Doctor streak:** after the night resolves, update
  `saveStreak = { targetId, count }`. If the doctors chose the same player as last
  time, `count++`. Otherwise reset it to that player with `count: 1`. If no doctors
  were alive that night, reset it to null. A target is blocked when
  `saveStreak.targetId === t && saveStreak.count >= 2`. If a blocked target arrives
  in a `select`, reject it.
- The host validates every `select`/`lock`: the sender maps to a player, the phase is
  night, the sender is alive and has a night role, the target is eligible for that
  role, and the sender hasn't locked yet.
- **Privacy:** a player's view includes selections and choices **only for their own
  team**. Civilians, jesters and other teams never receive another team's
  selections. Test this.
- **Decoy question for civilians and jesters (so no phone looks different):** each
  night the host picks one question at random (with `rng`, never repeated in a game)
  from a `QUESTIONS` array of ~30 funny, light roast-style prompts exported from
  game.js, e.g. "Who do you secretly not like the most?", "Who would survive a
  zombie apocalypse?", "Who would forget their own birthday?", "Who's most likely to
  get arrested on holiday?", "Who gives the worst advice?". Keep them playful, not
  cruel.
  - **Question source:** the free Truth or Dare Bot API
    `GET https://api.truthordarebot.xyz/api/paranoia?rating=pg|pg13` (CORS `*`,
    returns `{ id, question, ... }`, rate limit 5 per 5 s). Only the **host** fetches,
    in main.js, never in game.js. The fetch runs in the background while the game is
    in `roles`, `dawn` or `verdict` (i.e. before each night), with a 3 s timeout
    (AbortController). The result goes into `state.nextQuestion = { id, text }`
    through a pure setter in game.js. If the id or text was already used this game
    (`state.usedQuestions`), retry once. When the night starts, game.js uses
    `state.nextQuestion` if set, and otherwise picks an unused entry from the
    built-in `QUESTIONS` list with `rng`. If all of those are used too, it allows
    repeats. Any fetch error just leaves the fallback in place, and the night never
    waits on the network.
  - Lobby config gets `spice: 'pg' | 'pg13'` (default `'pg'`), shown as a host-only
    toggle "Questions: Mild / Spicy" that everyone else sees read-only.
  - Every alive civilian/jester gets that question as their night screen. Targets
    are alive players except self. They use the same `select` → `lock` actions, with
    no teammates and no chips. Their answers go to
    `funLog: [{ round, question, answers: { playerId: targetId } }]`.
  - **Same look:** all night action screens (mafia, doctor, detective, question) use
    one identical layout: a prompt at the top, the player list, and a "Lock in" button
    at the bottom, all in the same neutral night palette. No red mafia styling at
    night, and no big role-coloured headers. Teammate chips are small. From a glance
    across the table, every phone should look the same.
  - The night waits for **every alive player** to lock (all teams plus all question
    answerers). After locking, everyone sees the same "Waiting for others… k / m"
    screen, where m = all alive players. Detectives see their result card on that
    waiting screen.
  - Dead players get the spectator screen and no question.
  - Answers are private until the game ends. Never include `funLog` in any view
    before `over`.
- A team with no living members is skipped (only mafia is always required).
- When every team has resolved and every question answerer has locked, finish the night:
  - The kill target is `night.choice.mafia`. They survive if
    `night.choice.doctor === killTarget`. Otherwise they die (`alive=false`).
  - `lastEvent = { type:'night', killedId }`. Update `saveStreak`, then run the win
    check (mafia parity only). If the game isn't over → phase `dawn`.

### Dawn (reveal, everyone at once)

- Everyone gets the same view at the same moment: "☀ <name> was killed" or "Nobody
  died tonight" (the save is not revealed). Roles are **not** revealed on death.
- The host auto-advances to `vote` after 6 s (host-side `setTimeout`; the timer is
  re-armed if the host reloads into a timed phase). The view shows a progress bar.

### Vote (discuss & vote)

- Alive players see every alive player **except themselves**, plus "Skip". They
  select one and confirm with "Lock vote". Locked votes are final.
- Everyone sees `k / m voted` and who has voted so far (names only, not targets).
- Dead players see a read-only spectator screen.
- When all alive players have voted, tally:
  - `top` = the player(s) with the most votes. Someone is eliminated only if
    exactly one player has the top count and that count is greater than the skip
    count. Otherwise nobody is eliminated.
  - `lastEvent = { type:'vote', eliminatedId, tally }`. The tally maps each target to
    the names of those who voted for them (votes are public once revealed).
  - Win check, then phase `verdict` (if the game is over, still show the verdict
    first, then `over`).

### Verdict

- Animated tally (bars grow, voter names fade in), then "<name> was voted out" or
  "No one was voted out". Auto-advance after 7 s to `night` with `round++` and night
  picks cleared, or to `over`.

### Win check (in this order)

1. A jester eliminated **by vote** → `jester` wins (winnerIds = that jester). A
   jester killed at night just dies.
2. Alive mafia = 0 → `town` wins.
3. Alive mafia ≥ alive non-mafia (jesters count as non-mafia) → `mafia` wins.

Check after the night resolves and after the vote is tallied.

### Over

- Winner banner, every player's role revealed, and the dead marked.
- **"Night questions" section** below it: one card per round with the question, the
  most-picked player as the "winner" (ties listed together), and who picked whom
  (names, with staggered fade-in). It's included in the view only in `over`.
- Host: "Play again" → `lobby` with the same players (keep connected players, drop
  disconnected ones) and the same config.

### Disconnected players mid-game

- Disconnected players show a dimmed "offline" badge everywhere.
- The game waits for them (they usually come back after phone sleep).
- The host sees a "Remove" button next to each disconnected player in the
  night/vote/roles phases. Removing marks them dead (no role reveal, no event),
  drops their pending requirement, re-checks whether the phase can resolve, and runs
  the win check (where removal counts like a night death, so no jester win).

### viewFor(state, id) — only what this player may know

`{ code, phase, round, you: { id, name, role, alive, isHost }, players: [{ id, name,
alive, connected, isHost }], config, ...phaseData }`. The phase data includes
targets for this player, `locked`/`myPick`, teammates with their live selections and
lock state (own team only), the team choice, blocked doctor target, `detectiveLog`
(detectives only), counts, `lastEvent` (for dawn/verdict), and
`winner` + every role (only in `over`). **Test that a civilian's view contains no
other player's role.**

## UI (src/main.js + style.css)

- Mobile-first: `max-width: 480px`, centered, with a nice backdrop on wide screens.
  Use `100dvh`, `env(safe-area-inset-*)` padding, tap targets ≥ 48px, no horizontal
  scroll. `<meta name="viewport" content="width=device-width, initial-scale=1,
  viewport-fit=cover">` and a `theme-color`.
- **Render names with `textContent` only, never innerHTML, for anything containing
  player input** (names are XSS vectors).
- Rendering: compute a `screenKey = phase + round + (you.alive) + (locked)`. Rebuild
  the screen (with its enter animation) only when the key changes. Otherwise patch
  dynamic parts in place (counts, player list, badges, teammate picks), so animations
  don't replay and the local selection isn't lost on every view update. Keep the
  selected target in local UI state.
- Screens: Home (name input, Create room, Join with code input that auto-fills from
  `?room=`), Lobby, Role card, Night (action or wait), Detective result, Dawn,
  Vote, Verdict, Dead/spectator, Over, plus error/connecting states.
- Lobby: big room code, a Share button (`navigator.share`, falling back to clipboard
  with a toast), the player list with a host crown and "you" tag, and role steppers
  (− value +) with validation text. Host-only controls are hidden for others. The
  host can kick in the lobby (a removed peer gets `err` "Removed by host" and returns
  Home).
- Look: a dark "noir" theme. Deep navy/ink background, crimson accent for mafia and
  danger, gold for highlights, soft glassy cards with backdrop blur. Google Fonts:
  a display serif for headings (e.g. "Cinzel" or "Playfair Display") and "Inter"
  for body text. All colors are CSS custom properties on `:root`.
- Animations (CSS only, respecting `prefers-reduced-motion`):
  - screen enter: fade and slide up
  - role card: 3D flip on tap
  - night: slow starfield/twinkle background, moon glow
  - dawn: background shifts to warm sunrise. The killed name fades in with a red
    glow, and "Nobody died" gets a soft gold glow.
  - selection: the chosen player card scales and glows. The lock button pulses
    once when locked.
  - verdict: tally bars grow from 0, staggered.
  - over: CSS confetti/particles in the winner's color
  - `navigator.vibrate(…)` on dawn and verdict where supported (feature-check it)
- Screen Wake Lock: `navigator.wakeLock.request('screen')` when a room is joined,
  re-acquired on `visibilitychange`, all wrapped in try/catch.
- A toast component for errors/info.

## Edge cases checklist (all must be handled)

- Start blocked: fewer than 3 players, roles > players, mafia ≥ non-mafia, mafia = 0.
- Duplicate or empty or overlong names, room full (20).
- Joining a non-existent room → timeout message. Joining mid-game → error.
- Action spoofing: the host validates the sender (peerId → player), phase, role,
  alive, target validity and double-locking for every `act`.
- Mafia can't target mafia. Detectives can't target detectives. Doctors can't pick
  the player they chose on each of the last 2 nights. Voters can't vote for
  themselves or for dead players.
- Each team (mafia/doctor/detective): live shared selections, changeable until
  locked. It resolves only when all living members have locked: plurality, with a
  random tiebreak. The detective result is shown for the team's resolved target
  only.
- Night with no alive doctor/detective works (only mafia required).
- Vote ties and skip-heavy votes → no elimination.
- Jester night death ≠ jester win. Jester voted out = jester win, ahead of the other
  checks.
- Mafia parity reached at night → mafia win, without a dawn/vote.
- Disconnect / reconnect (same token), host reload resume, the host's Remove for
  stuck players.
- Dead players can't act and get the spectator screen.
- Re-render without replaying animations or losing the selection.

## Self-check (src/game.test.js)

A plain `node:assert` script, no framework. It covers: config validation cases,
role distribution counts, the night kill/save, the team detective result (including
the jester as not Mafia, shown only after all detectives lock), the team tiebreak with
injected rng, changing a selection, select rejected after lock, no resolution while a
teammate is unlocked, the doctor 2-nights-in-a-row block and streak reset, a
civilian/doctor view containing no mafia selections, the night not resolving until
civilian question answers are locked, `funLog` absent from views before `over`, vote tally (clear winner,
tie, skip ≥ top), all three win conditions plus the jester night death, rejected
illegal actions, and a civilian's `viewFor` leaking no roles. `npm test` must pass,
and `npm run build` must succeed.

## Narrator mode (`config.narrator`, host toggle "Runs the game: App / Narrator")

- The host gets no role and doesn't count for setup validation or win checks.
- After the role cards, the phase becomes `narrate` once every player has tapped
  "I'm ready". There are no nights, votes or questions in the app; the host runs
  them out loud.
- Players see a rotating witty "look up, the Narrator is speaking" screen, with no
  role on it (hold-to-peek still works). Their page stays connected.
- Only the host's `narrate` view has `roles`. The host taps a player to mark them
  `killed` / `voted` / back `alive`, and the normal win check runs after each mark
  (a voted-out jester wins) → `over`.
- Host `newgame` (any phase, after a confirm) returns everyone to the lobby without
  re-entering the code.
